Category Overview

For the Databases category, I selected the persistence layer of my Weight Tracking App. The original implementation relied on raw SQLite queries, which were functional but lacked structure, compile‑time validation, and modern best practices. Enhancing this artifact required migrating the entire data layer to Room, Android’s object‑relational mapping (ORM) framework.

This enhancement demonstrates my ability to redesign and modernize a database system using industry‑standard tools while improving reliability, maintainability, and security.

Enhancement Plan

The enhancement focused on replacing raw SQLite queries with Room, a modern ORM that provides compile‑time query validation, entity modeling, and safer asynchronous operations. This required restructuring the entire persistence layer, updating UI components, and ensuring compatibility with Kotlin coroutines.

Key Improvements

  • Entity Classes: created strongly‑typed models representing database tables.
  • DAO Interfaces: replaced raw SQL with annotated query methods.
  • Room Database: centralized database configuration and migration logic.
  • Coroutines Integration: ensured safe background execution for all queries.
  • UI Consistency: updated fragments and adapters to use new data sources.

Before (Raw SQLite)

// Raw SQL insert
db.execSQL("INSERT INTO weights (value, date) VALUES (" + weight + ", '" + date + "')");

After (Room ORM)

// DAO insert
@Insert
suspend fun insertWeight(entry: WeightEntry)

These changes significantly improved reliability, reduced boilerplate code, and ensured safer database interactions across the entire application.

Course Outcome Alignment

This enhancement demonstrates:

  • Database design: through structured entity modeling and schema definition.
  • Secure data management: by eliminating unsafe raw SQL and adopting validated queries.
  • Modern persistence techniques: using Room, DAOs, and coroutines.
  • Architectural refinement: improving separation of concerns across UI, logic, and data layers.
  • Performance optimization: ensuring queries run asynchronously without blocking the UI.

Artifact Narrative

Description

The original persistence layer relied on raw SQLite queries embedded directly in UI components. While functional, this approach made the code difficult to maintain, error‑prone, and vulnerable to SQL injection if not carefully sanitized.

Justification for Inclusion

I selected this artifact because it provided a clear opportunity to demonstrate database modernization and secure design principles. Migrating to Room required a deep understanding of schema design, asynchronous operations, and architectural best practices.

Reflection

Enhancing this artifact taught me how important it is to use modern persistence frameworks that enforce structure and safety. Room’s compile‑time validation prevented several subtle bugs that existed in the original implementation.

This enhancement strengthened my confidence in designing secure, maintainable database systems and integrating them into larger application architectures.
