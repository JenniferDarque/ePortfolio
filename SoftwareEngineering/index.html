Category Overview

For the Software Engineering and Design category, I selected a 3D rendering project originally developed in C++ and OpenGL. This artifact demonstrates full control over the graphics pipeline through custom GLSL shaders, including a vertex shader responsible for matrix‑driven coordinate manipulation and a fragment shader that computes realistic surface textures and lighting.

Enhancing this artifact allowed me to demonstrate modular software engineering, shader architecture improvements, and rendering pipeline refinement. The project’s complexity made it an ideal candidate for showcasing advanced engineering skills and thoughtful system design.

Enhancement Plan

The enhancement focused on upgrading the lighting model from Phong to Blinn‑Phong and reorganizing the rendering pipeline into a more modular architecture. This required coordinated updates across the fragment shader, vertex shader, and C++ rendering pipeline.

Shader Enhancements

The original fragment shader used Phong specular reflection, which relies on a reflection vector. Blinn‑Phong replaces this with a half‑vector, improving performance and producing smoother highlights. 

vec3 halfVector = normalize(lightDir + viewDir);
float spec = pow(max(dot(normal, halfVector), 0.0), material.shininess);

Additional improvements included normalizing transformed normals, separating texture sampling from lighting math, and adding a uniform toggle to switch between lighting models.

C++ Rendering Pipeline Enhancements

  • ShaderProgram class: encapsulates shader compilation, linking, and uniform handling.
  • RenderableObject class: manages VAOs, VBOs, and draw calls.
  • Scene class: organizes lights, camera, and objects into a structured scene graph.

Pseudocode Summary

// Blinn-Phong specular calculation
vec3 lightDir = normalize(light.position - fragPos);
vec3 viewDir = normalize(viewPosition - fragPos);
vec3 halfVector = normalize(lightDir + viewDir);

float spec = pow(max(dot(normal, halfVector), 0.0), material.shininess);

Artifact Narrative

Description

This artifact is a custom 3D graphic rendering inspired by Indianapolis’s Monument Circle. While the real location is far more complex and detailed, this version is intentionally simplified to fit the project scope and allow for creative experimentation. The original version was created in 2023, and the enhanced version was completed during this Capstone Project.

Justification for Inclusion

I selected this artifact because it offered a wide range of opportunities for meaningful enhancement. The original project had a solid foundation but was limited in its lighting capabilities and overall modularity. Enhancing it demonstrated skills in graphics programming, shader development, C++ architecture, debugging, and mathematical reasoning.

Reflection

Enhancing this artifact taught me the importance of precision in graphics programming. Even a single missing uniform, such as the camera’s position, can break an entire lighting system and result in a black screen. I learned how critical it is for C++ structures and GLSL structs to match exactly.

The process was challenging but rewarding. Refactoring the LightingManager revealed deeper issues in the camera system, requiring a complete overhaul. Each change uncovered new incompatibilities, but overcoming these obstacles strengthened my problem‑solving skills and increased my confidence in enhancing and refactoring existing codebases.
